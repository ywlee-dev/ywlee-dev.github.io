앱 구조 기초 — 뇌 · 팀 · 몸

예시는 Electron · Vue 앱이지만 Flutter · React 든 같은 모양이다. 그림 속 파일 이름은 설명용 예시.

앱 코드가 커지면 "이거 고치면 어디가 깨지지?"가 무서워진다. 이 페이지는 그 걱정을 줄이는 틀 하나를 몸에 빗대어 보여 준다. 처음이면 바로 아래 칸만 읽어도 된다 — 3분.

먼저 이것 하나 — 깨움은 내려가고, 울림은 올라온다

등장하는 것은 넷. 🧠 뇌(앱의 맨 위 코드), 팀마다 있는 🔌 배선(잇는 코드)과 📘 룰(판단하는 코드), 그리고 ⚙️ 장비(일하는 부품 = 몸).

초인종으로 생각하면 — 켤 때 반장(배선)이 초인종(장비)에 자기 번호를 적어 둔다. 초인종은 반장이 무슨 일을 할지 모른다. 눌리면 적힌 번호로 울릴 뿐이고, 판단할 것은 반장이 지침서(룰)에 묻는다.

👉 눌러 보는 그림 — 배선은 릴레이, 룰은 카드 : 선을 꽂고 → 울리고 → 묻고 → 붙이는 걸음을 코드 줄과 함께 하나씩 본다.

네 줄로

🧠깨움은 내려간다 — 뇌 → 팀 배선 → 장비.
켤 때 한 번. 그 뒤 뇌(main.js · App.vue)는 쉰다
🖐팀마다 배선이 잇고 · 룰이 판단하고 · 장비가 움직인다.
팀 = 기능 하나의 폴더
🔁울림은 올라온다 — 장비 → 자기 팀 배선까지만.
오른손 신호는 오른손 쪽에서 끝낸다
🗄️팀끼리는 보관함에서 만난다.
남의 팀 몸을 바로 움직이지 않는다

예 하나 — 숫자 8080 이 화면에 뜨기까지

설정 파일(config.json)에 적힌 포트 숫자를 읽어, 화면 맨 위 줄에 "수신 포트: 8080" 을 보여 주는 작은 앱.

  1. 🧠 앱을 켜면 뇌가 설정 팀 · 펌프 팀 · 머리줄 팀의 배선을 깨운다. 배선마다 자기 장비를 깨우거나 센서(🔔)를 단다. 그리고 뇌는 쉰다.
  2. 설정 팀 배선이 📄 서류함에게 "읽어" → 숫자 8080 → 📘 룰에게 "괜찮아?" → "1~65535 사이, OK".
  3. 펌프 팀 배선이 그 숫자를 받아 🗄️ 보관함에 넣는다. 넣기만 하고, 누가 쓸지는 모른다.
  4. 머리줄 팀 배선이 켤 때 보관함에 걸어 둔 콜백이 울린다(🔔). 그 콜백이 📘 룰에게 "뭘 보여 줄까?" → "8080".
  5. 🖼️ 머리줄 화면이 "수신 포트: 8080" 을 그린다. 화면은 받은 대로 그리기만.

그래서 좋은 점 — 고칠 때 한 곳만 연다

  • 기준이 바뀌면 (기본 포트 · 몇 초) → 📘 룰 한 장만
  • 화면 모양 · 통신 방식이 바뀌면 → ⚙️ 장비 하나만
  • 새 기능이 생기면 → 🖐 팀 하나를 더하고, 뇌에 깨우는 줄 하나
  • 이상하면 → "이 장비에 누가 센서를 달았나?" — 그 팀 하나만 열면 된다

3켤 때 — 깨움은 두 단계로 내려간다뇌는 팀 배선만, 장비는 팀 배선이 깨운다

뇌는 팀 배선의 켜는 손잡이만 당긴다. 그 팀의 장비는 팀 배선이 깨운다 — 배선은 "잇는 사람"이라 자기 장비를 준비시키는 것도 배선의 일.

팀 배선의 켜는 손잡이그 안에서 깨우는 것
startConfigRoom()서류함에 "읽어"(📞) → 룰에 확인(📘) → 들고 있기
startIpcPump()창구에 "설정 줘" 전화(📞) → 답에 센서 .then(🔔)
광고 팀 onInit()전화기에 "내 IP?"(📞) → 망 감지기에 센서 listen(🔔)

깨우는 모습은 둘 — 📞 한 번 시키고 답을 받아 끝(파일 읽기), 🔔 센서를 달아 두고 기다림(버튼 · 소켓 · 보관함). 바로 받는 답(return)은 울림이 아니고, 나중에 걸어 둔 콜백이 불리는 것이 울림이다.

📘 룰은 깨우지 않는다. 켜 둘 것이 없는 종이라서, 필요할 때 펼쳐 묻기만 한다.

장비가 서너 개인 팀도 뇌가 당기는 손잡이는 보통 하나다. ✕ 예: 뇌(main)가 광고 SDK 준비 장비를 직접 부른다 — 한 줄이라 당장 꼬이진 않지만, 그 팀에 켤 때 할 일이 늘면 그 팀 배선의 손잡이 안으로 옮긴다.

4일이 생기면 — 울림은 자기 팀 배선으로 올라온다울림 → 걸어 둔 콜백 → 룰 → 움직임. 그 팀 안에서 끝

울린 몸의 주인 팀이, 그 팀 안에서: 몸이 울림 → 그 팀 배선 → 그 팀 룰 → 몸이 움직임. 오른손 신호는 오른손 교차로에서.

센서를 단 팀이 처리한다. 보관함 센서는 머리줄 배선이 달았으니, 보관함이 바뀌면 머리줄 방 안에서 끝난다 — 설정 방이나 뇌로 넘어가지 않는다. 그래서 "이 신호는 어디서 처리하나?"는 "이 장비에 누가 센서를 달았나?"로 찾는다. 물을 것이 없으면 📘 칸은 건너뛴다.

울리면 배선 파일 전체가 아니라, 걸어 둔 콜백만 돈다.

☀️ 켤 때 한 번 도는 줄
function startHeader() {
  store.onChange( … );  // 🔔 번호만 적어 둠
}                       // 여기서 끝
🔔 바뀔 때마다 도는 줄 ( … 자리)
(port) => {
  const text = portToShow(port);  // 📘 묻고
  headerBar.draw(text);          // 📞 움직임
}

설명용으로 줄인 코드. startHeader() 는 다시 돌지 않는다. Vue 에서는 computed · watch, Flutter 에서는 Obx · listen 이 이 센서 자리다.

아는 방향은 한쪽이다. 배선은 장비를 가져오지만(import), 장비는 배선을 가져오지 않는다 — 켤 때 받은 콜백만 부른다. 그래서 장비를 다른 팀 · 다른 앱에 옮겨 써도 된다. 화면만은 예외로, 버튼에 거는 한 줄에서 배선 함수의 이름을 안다(7번).

다른 장비로 가도 괜찮나? 가르는 질문 하나 — "A 장비에 센서를 단 배선"과 "B 장비를 부르는 배선"이 같은 팀인가? 같은 팀이면 한 교차로 안(손끝 → 팔 근육처럼). 다른 팀이면 아래 5번처럼 만나는 장비를 거친다.

5팀에서 팀으로 — 만나는 장비에 내려놓는다팀 밖으로 갈 땐 보관함 · 창구를 거친다

한 바퀴는 같은 팀 안에서 묶는다. 팀 밖으로 갈 땐 바로 잇지 않고, 보관함 · 창구 같은 만나는 장비에 내려놓고 끝낸다.
