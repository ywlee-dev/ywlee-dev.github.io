앱 구조 기초 — 뇌 · 배선과 룰 · 몸(장비)

위에서 아래로 — 0칸(말 정리) 다음 열 칸. 예시는 Electron · Vue 앱이지만 Flutter · React 든 같은 모양이다. 그림 속 파일 이름은 설명용 예시.
한 줄로: 🧠 뇌는 팀 배선만 한 번 깨우고 쉰다(장비는 팀 배선이 깨운다) · 🖐 일은 팀마다 자기 안에서 끝낸다 · 🚧 팀 경계를 넘어 엉키는 흐름은 피한다 — 넘어야 하면 보관함 · 창구 같은 장비를 사이에 두고 만난다 · 🗄️ 같이 쓰는 장비는 바꾸는 주인이 한 팀.

끝말 .mech · .rules · .wiring 은 이 페이지가 정한 이름 약속이다 — 언어나 프레임워크의 규칙이 아니다. 파일 이름만 보고 그 파일이 무슨 종류인지 알게 하려고 붙인다.

1한 장 — 뇌에서 내려오는 흐름

뇌 자리도 방과 같은 모양 — 배선 하나 + 룰 하나. 기능마다도 배선 + 룰. 그 아래 청록은 팀마다 자기 몸(장비).

↔ 그림을 옆으로 밀어 보세요

청록 상자 그 팀의 손발 — 설정 방은 서류함, 머리줄 방은 머리줄 화면. 보관함은 두 팀이 만나는 곳, 라이브러리는 모두가 꺼내 쓰는 공용. 주황 ↑ 몸에서 신호가 올라옴(울림) · 청록 ↓ 배선이 몸을 움직임(부름) · ● 깨어 있는 팀 (○ 아직 없음, 다음 기능). 한 파일은 한 가지만 — 맨 위 배선은 켜고 잇고 묻기만, 판단은 룰이 한다. 앱 전체 판단(첫 화면 등)은 앱 전체 룰, 기능 판단은 그 기능의 룰 — 척수 반사처럼 그 자리에서.

뇌는 아침에 한 번 팀들의 눈을 뜨게 하고 "이제 너희가 알아서 해" 하고 쉰다. 그 뒤 주황 ↑ · 청록 ↓ 는 각 팀이 스스로 도는 것 — 뇌로 다시 올라가지 않는다. 로그아웃처럼 앱 전체에 영향이 가는 일도, 그 일을 맡은 팀(예: 로그인 팀)이 자기 센서로 알아채 처리한다.

2켤 때 — 깨우기는 두 단계

뇌는 팀 배선의 켜는 손잡이만 당긴다. 그 팀의 장비는 팀 배선이 깨운다 — 배선은 "잇는 사람"이라 자기 장비를 준비시키는 것도 배선의 일.

↔ 그림을 옆으로 밀어 보세요

팀 배선의 켜는 손잡이그 안에서 깨우는 것
startConfigRoom()서류함에 "읽어"(📞) → 룰에 확인(📘) → 들고 있기
startIpcPump()창구에 "설정 줘" 전화(📞) → 답에 센서 .then(🔔)
광고 팀 onInit()전화기에 "내 IP?"(📞) → 망 감지기에 센서 listen(🔔)

✕ 예: 뇌(main)가 광고 SDK 준비 장비를 직접 부른다 — 한 줄이라 당장 꼬이진 않지만, 그 팀에 켤 때 할 일이 늘면 그 팀 배선의 손잡이 안으로 옮긴다.

가르는 질문 하나 — "혼자 떼어 놓으면 뭘 하나?"

하는 일예

배선 안에 if · 숫자가 생기면 → 룰로 옮길 신호.

4화면은 한 줄만 건다

버튼에 콜백을 거는 한 줄은 화면에. 콜백 안의 내용은 배선에.

↔ 그림을 옆으로 밀어 보세요

✅ 이렇게 — 화면엔 한 줄
<!-- Vue -->
<button @click="login.submit()">로그인</button>

// Flutter
onPressed: () => loginWiring.submit(email, pw)
✕ 이렇게 말고 — 화면 안에 흐름
onPressed: () async {
  if (!LoginRules.canLogin(e, p)) return;  // 판단
  await server.signIn(…);                  // 전화
  if (…) showDialog(…);                    // 판단 + 그리기
  router.go('/home');                      // 이동
}

그래서 화면을 갈아 끼워도 흐름은 배선에 그대로 남는다. 어느 버튼에 무엇이 걸렸는지는 화면 파일만 열어도 보인다.

5장비에 붙은 작은 배선 — 괜찮은 선

요즘 장비는 센서와 작은 배선을 달고 나온다(Obx · setState · computed · watch). 억지로 떼지 않아도 된다 — 세 가지만 지키면.

↔ 그림을 옆으로 밀어 보세요

지킬 것보는 법
① 판단은 룰에 묻는다장비 안 if 의 기준 · 숫자가 룰 파일에 있나 — 장비는 Rules.○○() 를 부르기만
② 팀 밖 장비는 안 움직인다자기 팀 보관함을 보고 자기만 그린다
③ 커지면 뗀다배선 줄이 길어짐 · 같은 흐름을 다른 장비도 씀 · 시험하기 어려움 → 그 팀 .wiring 으로

그리고 섞였다는 걸 이름표에 적는다 — 파일 맨 위 한 줄: // 장비 · 배선 섞임 — 보관함 보고 다시 받기. 흐름을 찾을 때 "이 장비 안에도 배선이 있구나" 하고 바로 열어 본다.

6일이 생기면 한 바퀴 — 그 팀 안에서 끝난다

울린 몸의 주인 팀이, 그 팀 안에서: 몸이 울림 → 그 팀 배선 → 그 팀 룰 → 몸이 움직임. 오른손 신호는 오른손 교차로에서.

↔ 그림을 옆으로 밀어 보세요

센서를 단 팀이 처리한다. 보관함 센서는 머리줄 배선이 달았으니, 보관함이 바뀌면 머리줄 방 안에서 끝난다 — 설정 방이나 뇌로 넘어가지 않는다. 그래서 "이 신호는 어디서 처리하나?"는 "이 장비에 누가 센서를 달았나?"로 찾는다. 물을 것이 없으면 📘 칸은 건너뛴다.

다른 장비로 가도 괜찮나? 가르는 질문 하나 — "A 장비에 센서를 단 배선"과 "B 장비를 부르는 배선"이 같은 팀인가? 같은 팀이면 한 교차로 안(손끝 → 팔 근육처럼). 다른 팀이면 다음 칸처럼 만나는 장비를 거친다.

7팀에서 팀으로 — 만나는 장비에 내려놓는다

한 바퀴는 같은 팀 안에서 묶는다. 팀 밖으로 갈 땐 바로 잇지 않고, 보관함 · 창구 같은 만나는 장비에 내려놓고 끝낸다.

↔ 그림을 옆으로 밀어 보세요

그래서 앱 전체는 팀 안의 작은 한 바퀴들이 보관함을 사이에 두고 이어진 모양이다. 한 바퀴를 고쳐도 다른 팀의 바퀴는 안 흔들린다.

8여러 팀이 같이 쓰는 장비

있어도 된다 — 단, 바꾸는 주인은 한 팀. 나머지는 읽거나 불러 쓰기만.

↔ 그림을 옆으로 밀어 보세요

처음엔 한 팀 안에 두고, 두 번째 팀이 실제로 쓰기 시작하면 공용 자리(shared/)로 옮긴다.

9무엇이 바뀌면 어디를 고치나

바뀐 것고칠 곳
기준 · 숫자 (기본 포트, 끊김 3초 → 5초)📘 룰만
바깥 방식 · 화면 모양 (파일 형식, 통신, 버튼 위치)⚙️ 장비만
새 일 (머리줄에 사용자 이름도)⚙️ 장비 + 🔌 배선 한 줄 (+ 필요하면 📘)
새 기능 (방 하나 더)🔌 배선 + 📘 룰 한 벌, 그리고 🧠 뇌에 켜는 줄 하나
두 번째 팀이 같은 장비를 쓰기 시작함⚙️ 그 장비를 공용 자리(shared/)로 — 바꾸는 주인은 한 팀 그대로

코드를 읽을 때: 흐름이 궁금하면 배선 → 왜 이 값은 룰 → 어떻게 읽고 그리나는 장비.

읽는 법: 기능 하나에서 값 하나(예: 포트 숫자)를 들고, 몸 → 배선 → 룰 → 몸을 줄마다 "부르기 · 센서 · 묻기"라고 말하며 따라간다.

10경계가 무너지는 다섯 가지 신호

코드를 볼 때 다섯 중 하나가 보이면 "경계가 무너지는 중"이다.

↔ 그림을 옆으로 밀어 보세요

신호이렇게 찾는다이렇게 고친다
① 뇌에 if 가 는다main.js · App.vue · main.dart 에 기능 이름 · 기준 숫자가 보인다그 기능의 룰로 (앱 전체 판단이면 앱 전체 룰로)
② 남의 팀 속을 importA 팀 파일이 B 팀의 .mech · .rules 를 직접 가져온다B 가 보관함에 담고 A 는 그 보관함에 센서를 단다
③ 화면에 전화 · 판단 · 이동화면 파일 안에 서버 호출 · if · 화면 이동이 같이 있다그 팀 .wiring 의 함수 하나로 옮기고, 화면엔 거는 한 줄만
④ 여러 팀이 같은 장비를 바꾼다두 팀 파일이 같은 보관함에 쓰거나 같은 화면을 그린다바꾸는 주인을 한 팀으로 — 나머지는 센서 · 읽기만 (8칸)
⑤ 뇌가 팀 장비를 직접 깨운다뇌 파일(main)에 팀의 .mech 이름이 보인다그 팀 배선의 켜는 손잡이 안으로 (2칸)

한꺼번에 뜯지 않는다 — 새 코드부터 지키고, 이미 있는 코드는 그 파일을 고칠 일이 생겼을 때 나눈다.
